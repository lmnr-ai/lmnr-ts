# src/mock/ — observe-level mocks (LAM-2588 phase 4)

- When `LMNR_MOCK_URL` is set (an eval trial with mocks; server and protocol live in lmnr-python, `spec/lmnr-mock/` here is a byte-identical copy, never edit it here), an `observe`d function whose key the server lists is answered by `POST {url}/fn/{key}` instead of running. Works without `Laminar.initialize()`.
- **Cross-language parity surface** with lmnr-python `src/lmnr/sdk/mock/` (read its `AGENTS.md` for the shared rules: fail closed, backoff, outcomes, span attributes, error messages). `errors.ts`, `protocol.ts`, `client.ts`, `intercept.ts` are line-comparable with the Python modules; keep messages identical.
- **Key**: `ObserveOptions.mockKey`, else the span name (`name`, else `fn.name`); `mockable: false` → `mockKey: undefined` in `DecoratorConfig`, never consulted. `resolveMockKey` in `src/decorators.ts` is shared by `observe`, `observeDecorator` and `observeExperimentalDecorator`. Other `observeBase` callers pass no key and are never mocked.
- **Mocked functions must be declared `async`.** A mocked answer is a Promise, and turning a sync function's return value into one would break its callers. Detection is `Object.prototype.toString.call(fn) === "[object AsyncFunction]"`, the only check that holds before the function runs; a plain function that returns a Promise (`(q) => client.search(q)`) gets `MockedError("<key>: mocked TypeScript functions must return a Promise (declare the function async)")`. Only for mocked keys: unmocked sync functions are untouched. `GeneratorFunction` / `AsyncGeneratorFunction` → `"generators can't be mocked yet"`.
- **Sync throws, async rejects**: `mockCall` runs inside `observeBase`'s `try` around the call, so a failure of a sync function throws synchronously (and is recorded on the span); for an async function it is a rejected Promise, like an error the function would raise itself.
- **The key set is fetched synchronously** (differs from Python, which uses `httpx.AsyncClient` in async wrappers): `observe` must know whether a call is mocked before it runs the function, and for a sync function it can't wait for a Promise. Starting an async fetch and running unmocked-looking calls meanwhile would let a mocked key's real function run (fail open). Node has no sync HTTP, so `getSync` starts a short-lived `Worker` (`eval: true`, `execArgv: []` so the app's `--require` / `--import` hooks don't load) that does the GET with `node:http` and posts the result on a `MessageChannel`, while this thread blocks in `Atomics.wait` and reads it with `receiveMessageOnPort` (the synckit pattern). No child process: the isolation rules forbid `mock` in any command line in the container. Costs one worker start (tens of ms) per process, or per retry while the server is down. **Consequence for tests**: a fake server on the test's own thread deadlocks the first observed call; `test/mock.test.ts` runs it in a worker.
- **`node:http`, never `fetch`**, for both the worker GET and the calls: the server is on loopback and must not go through the app's proxy settings (`NODE_USE_ENV_PROXY`). Per-call timeout `LMNR_MOCK_TIMEOUT_MS` (default 30 s, socket idle timeout); keys: 2 s.
- **Args**: the argument array as the function got it, serialized with `toJson` (the span-input serializer; `undefined` in the array becomes `null`). Span input itself is unchanged (a single object arg is recorded unwrapped, the handler still gets `[obj]`).
- **Spans**: same attributes as Python (`lmnr.mock.key`, `lmnr.mock.outcome`, `lmnr.span.mocked` on respond / raise). The mocked Promise flows through `observeBase`'s existing Promise path, so output recording, `recordException` and stream detection need nothing extra. `MockedError.name` is the handler's error type, so the exception event's `exception.type` is e.g. `DuplicateRefund`.
- Tests: `test/mock.test.ts` (outcomes, failures, keys, backoff, function shapes, the experimental decorator, and the `spec/lmnr-mock/cases` conformance cases served back from their recorded responses).
