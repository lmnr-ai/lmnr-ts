# src/mock/ — observe-level mocks (LAM-2588 phase 4)

- When `LMNR_MOCK_URL` is set (an eval trial with mocks; server and protocol live in lmnr-python, `spec/lmnr-mock/` here is a byte-identical copy, never edit it here), an `observe`d function whose key the server lists is answered by `POST {url}/fn/{key}` instead of running. Works without `Laminar.initialize()`.
- **Cross-language parity surface** with lmnr-python `src/lmnr/sdk/mock/` (read its `AGENTS.md` for the shared rules: fail closed, backoff, outcomes, span attributes, error messages). `errors.ts`, `protocol.ts`, `client.ts`, `intercept.ts` are line-comparable with the Python modules; keep messages identical.
- **Key**: `ObserveOptions.mockKey`, else the span name (`name`, else `fn.name`); `mockable: false` → `mockKey: undefined` in `DecoratorConfig`, never consulted. `resolveMockKey` in `src/decorators.ts` is shared by `observe`, `observeDecorator` and `observeExperimentalDecorator`. Other `observeBase` callers pass no key and are never mocked.
- **No up-front checks on the function** (decided in review of #386, over the plan's "must be async" rule): a mocked call always returns a Promise. A function that isn't declared `async` (`Object.prototype.toString.call(fn) !== "[object AsyncFunction]"`) is still mocked, with one warning per key (`warnOnce`): a plain function that returns a Promise (`(q) => client.search(q)`) works unchanged, and a truly sync one hands its callers a Promise, which the eval run surfaces. Only generators (`GeneratorFunction` / `AsyncGeneratorFunction`) are refused, with `MockedError("<key>: generators can't be mocked yet")`.
- **The key set loads asynchronously**, started by the first observed call (`MockClient.mockedKeys`, one shared in-flight Promise). An `async` function waits for it, so it is never run unmocked. Any other function called before the keys have loaded runs as usual: it can't wait without changing what it returns. Once the keys arrive, `"<key> ran unmocked: it was called before the mock keys loaded"` is logged for each such key that turns out to be mocked. This replaced a synchronous fetch (a worker + `Atomics.wait`) whose only job was to close that window; the window is the first observed calls of a process, over loopback.
- **Fail closed** on an unreachable server: the load rejects, the backoff (100 ms → 2 s) starts, async functions reject and others throw (`startLoading` rethrows the last failure inside the backoff) with `MockedError("mock server unreachable (...)")`. The load's Promise always has a handler attached, so a load no caller awaits never becomes an unhandled rejection. `httpRequest` catches `request()` throwing synchronously (a malformed or `https:` `LMNR_MOCK_URL`, Bugbot on #386), so that is a failed load too.
- **Sync throws, async rejects**: `mockCall` runs inside `observeBase`'s `try` around the call, so a failure of a non-async function throws synchronously (and is recorded on the span); for an async function it is a rejected Promise, like an error the function would raise itself.
- **`node:http`, never `fetch`** (`httpRequest`, for the keys and the calls): the server is on loopback and must not go through the app's proxy settings (`NODE_USE_ENV_PROXY`). Per-call timeout `LMNR_MOCK_TIMEOUT_MS` (default 30 s, socket idle timeout); keys: 2 s.
- **Args**: the argument array as the function got it, serialized with `toJson` (the span-input serializer; `undefined` in the array becomes `null`). Span input itself is unchanged (a single object arg is recorded unwrapped, the handler still gets `[obj]`).
- **Spans**: same attributes as Python (`lmnr.mock.key`, `lmnr.mock.outcome`, `lmnr.span.mocked` on respond / raise). The mocked Promise flows through `observeBase`'s existing Promise path, so output recording, `recordException` and stream detection need nothing extra. `MockedError.name` is the handler's error type, so the exception event's `exception.type` is e.g. `DuplicateRefund`.
- **Trajectories keep the flag only**: the lmnr-atif collector keeps `lmnr.span.mocked` and the builder writes `tool_call.extra.lmnr.mocked: true` (see `src/trajectory/AGENTS.md`). `lmnr.mock.key` / `lmnr.mock.outcome` are dropped, and a mocked function that is neither an LLM call nor a tool isn't in the file.
- Tests: `test/mock.test.ts` (outcomes, failures, keys, backoff, calls before the keys load, non-async functions, generators, the experimental decorator, and the `spec/lmnr-mock/cases` conformance cases served back from their recorded responses). `warned` is exported so tests can check the warnings.
