# src/mock/ — observe-level mocks (LAM-2588 phase 4)

- When `LMNR_MOCK_URL` is set (an eval trial with mocks; server and protocol live in lmnr-python, `spec/lmnr-mock/` here is a byte-identical copy, never edit it here), an `observe`d function whose key the server lists is answered by `POST {url}/fn/{key}` instead of running. Works without `Laminar.initialize()`.
- **Cross-language parity surface** with lmnr-python `src/lmnr/sdk/mock/` (read its `AGENTS.md` for the shared rules: fail closed, backoff, outcomes, span attributes, error messages). `errors.ts`, `protocol.ts`, `client.ts`, `intercept.ts` are line-comparable with the Python modules; keep messages identical.
- **Key**: `ObserveOptions.mockKey`, else the span name (`name`, else `fn.name`); `mockable: false` → `mockKey: undefined` in `DecoratorConfig`, never consulted. `resolveMockKey` in `src/decorators.ts` is shared by `observe`, `observeDecorator` and `observeExperimentalDecorator`. Other `observeBase` callers pass no key and are never mocked.
- **Sync stays sync, async stays async, like Python** (decided in review of #386, over the plan's "must be async" rule and a later "always return a Promise" version): an `async` function (`Object.prototype.toString.call(fn) === "[object AsyncFunction]"`) gets a Promise and its request doesn't block. Any other function gets the mocked value synchronously: `mockedKeysSync` / `callSync` block the thread until the server answers. Types are erased by then, so there's no telling a plain function that returns a Promise (`(q) => client.search(q)`) from a sync one: it gets the value itself, which `await` still accepts but `.then` doesn't; declare it `async` for a Promise. Only generators (`GeneratorFunction` / `AsyncGeneratorFunction`) are refused, with `MockedError("<key>: generators can't be mocked yet")`. `mockCall` returns `{ result }` (a sync answer can be `undefined`) or `undefined` to run the function.
- **Blocking requests** (`requestSync` in `client.ts`): one long-lived worker (`eval: true`, CommonJS source in `WORKER`, `execArgv: []`, unref'd along with its port so it never keeps the app alive) makes each request; this thread posts it with its own `SharedArrayBuffer` flag, waits in `Atomics.wait` (the request's timeout + 3 s for the worker's startup), then reads the answer with `receiveMessageOnPort`, skipping answers to earlier requests that timed out (by id). The worker reports every failure as an answer; a worker that dies is replaced on the next request. Measured from the built dist (CJS and ESM): about 35 ms for the first call (worker start + keys), about 1.5 ms per call after. A mock server in the same thread would deadlock a sync call, which is why the tests' `FakeServer` runs in a worker; a trial's server is another process.
- **The keys**: a non-async function's first call fetches them blocking (`mockedKeysSync`), so nothing runs unmocked before they load; an `async` one awaits `mockedKeys` (concurrent first fetches are harmless: one that fails after another loaded the keys returns them, as Python's `amocked_keys` does; `test/mock.test.ts` pins it with an in-process HTTP server, fine for the async path). This replaced an async-only load where non-async calls made before it finished ran the real function. An empty `mockKey` falls back to the span name (`||`, Python's `mock_key or name`).
- **Fail closed** on an unreachable server: the fetch fails, the backoff (100 ms → 2 s) starts, and until `/keys` answers every observed call fails with `MockedError("mock server unreachable (...)")` (async functions reject, others throw); calls inside the backoff make no request. `httpRequest` and the worker catch `request()` throwing synchronously (a malformed or `https:` `LMNR_MOCK_URL`, Bugbot on #386), so that is a failed fetch too.
- **Sync throws, async rejects**: `mockCall` runs inside `observeBase`'s `try` around the call, so a failure of a non-async function throws synchronously (and is recorded on the span); for an async function it is a rejected Promise, like an error the function would raise itself.
- **`node:http`, never `fetch`** (`httpRequest`, for the keys and the calls): the server is on loopback and must not go through the app's proxy settings (`NODE_USE_ENV_PROXY`). Per-call timeout `LMNR_MOCK_TIMEOUT_MS` (default 30 s, socket idle timeout); keys: 2 s.
- **Args**: the argument array as the function got it, serialized with `toJson` (the span-input serializer; `undefined` in the array becomes `null`). Span input itself is unchanged (a single object arg is recorded unwrapped, the handler still gets `[obj]`).
- **Spans**: same attributes as Python (`lmnr.mock.key`, `lmnr.mock.outcome`, `lmnr.span.mocked` on respond / raise). Both paths share `settle` and flow through `observeBase`'s existing value / Promise paths, so output recording, `recordException` and stream detection need nothing extra. `MockedError.name` is the handler's error type, so the exception event's `exception.type` is e.g. `DuplicateRefund`.
- **Trajectories keep the flag only**: the lmnr-atif collector keeps `lmnr.span.mocked` and the builder writes `tool_call.extra.lmnr.mocked: true` (see `src/trajectory/AGENTS.md`). `lmnr.mock.key` / `lmnr.mock.outcome` are dropped, and a mocked function that is neither an LLM call nor a tool isn't in the file.
- Tests: `test/mock.test.ts` (outcomes, failures, keys, backoff, sync answers / timeouts / fail-closed retries for non-async functions, generators, the experimental decorator, and the `spec/lmnr-mock/cases` conformance cases served back from their recorded responses). `FakeServer` runs in a worker (see above).
