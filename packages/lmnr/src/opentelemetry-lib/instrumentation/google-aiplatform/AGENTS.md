# Google AI Platform (Vertex AI) instrumentation — LAM-2403

- Ported from OpenLLMetry's `instrumentation-vertexai` and named `google-aiplatform` (vertexai is the legacy name). The single `GoogleAIPlatformInstrumentation` covers two packages: `@google-cloud/vertexai` (`GenerativeModel` + `GenerativeModelPreview` → `generateContent` / `generateContentStream`) and `@google-cloud/aiplatform` (`PredictionServiceClient.predict` on the top-level / `v1` client AND the separate `v1beta1` prototype). `instrumentModules.google_aiplatform` accepts either module, an array of both, or the bare classes. `gen_ai.system` is `"vertex_ai"`.
- **The Vertex AI path reuses the google-genai helpers.** `toGenAiParams` reshapes the call into genai's `{model, contents, config}` and passes it to `setRequestAttributes(..., system)` / `setResponseAttributes`. Model-level state lives on the instance (`this.model`, `this.generationConfig`, `this.systemInstruction` already formulated as a `{role:"system", parts}` Content, `this.tools`). Request-level `generationConfig` / `systemInstruction` / `tools` REPLACE the model-level values, they are not merged, because that is what the SDK sends. Fields are camelCase. Upstream read snake_case `generation_config.max_output_tokens` and the request's `generationConfig` only, so it silently dropped model-level params. `this.model` may be `models/x` or a full `projects/.../models/x` path, so only the last path segment is recorded. `modelVersion` is not always present, so `gen_ai.response.model` falls back to the request model.
- **The stream span ends from `result.response`, not by wrapping `result.stream`.** `generateContentStream` resolves to `{stream, response}`. `response` aggregates on its own tee'd branch of the body, so it settles even when the caller never drains `stream`, and it yields the merged candidates and usage directly. The result is returned untouched.
- **`predict` has callback overloads** (`(req, cb)` and `(req, opts, cb)` return void). If the last arg is a function, it is wrapped to finish the span. Otherwise the promise resolves to `[response, request, {}]`, and the response is `result[0]`. Request and response payloads are `google.protobuf.Value` trees. `fromValue` decodes both plain objects (`helpers.toValue` output) and protobufjs instances, where unset oneof members default to `null` and the `kind` getter names the set one. Upstream used truthiness checks, which dropped `temperature: 0` and crashed on missing fields; ours uses `typeof === "number"`.
- Patch state lives on each prototype under a symbol (`{traceContent, original}` per method), so a re-`initialize()` only refreshes `traceContent`. Attribute-extraction failures are swallowed and logged via pino `logger.debug`, never thrown into the user's call. Tests (`test/google-aiplatform.test.ts`) need no cassettes: Vertex AI uses global `fetch` (stubbed, with a fake `googleAuth.getAccessToken`), and `PredictionServiceClient` is stubbed by pre-setting `predictionServiceStub` and replacing `innerApiCalls.predict`.
- Not covered yet (follow-ups): `ChatSession.sendMessage*` (it calls `generateContent` functions directly, bypassing the model methods), `countTokens`, and aiplatform `generateContent` / `streamGenerateContent` on `PredictionServiceClient`.
