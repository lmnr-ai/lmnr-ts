# OpenAI instrumentation — LAM-2409

- This is a port of the Python SDK's `opentelemetry_lib/opentelemetry/instrumentation/openai` (v1 wrappers + `responses_wrappers.py`). It replaces `@traceloop/instrumentation-openai`, and that dependency is gone. `instrumentModules.OpenAI` (and the deprecated `openAI`; passing both throws) accepts the module namespace, the default export, or the client class.
- **Span names are fixed, not `<op> <model>`:** `openai.chat`, `openai.completion`, `openai.embeddings`, `openai.decision`, `openai.response`. All are LLM spans. The traceloop spans were named `chat gpt-4.1-nano`; the recorded cassette test was updated. Image generation spans (traceloop had them) are dropped, like Python.
- **Patch targets (v4+):** `create` on `Chat.Completions`, `Completions`, `Embeddings`, `Decisions` prototypes, plus `create` / `retrieve` / `cancel` on `Responses`. Prototypes are reached through the client class (`OpenAI.Chat.Completions`, ...). `chat.completions.parse()`, `.stream()` and `runTools()` all go through `create`, so patching them too would nest a second span. Patch state lives on each prototype under a symbol, keyed by method name; a re-`initialize()` only refreshes `traceContent`.
- **`create` returns an `APIPromise`, and the wrapper keeps it one** — same pattern as Anthropic: box the original call in `Laminar.withSpan`, finish via `result._thenUnwrap(succeed)`, attach `fail` to `_responseProps?.() ?? responsePromise` (HTTP/connection errors reject there). `withResponse()` is pinned by a test.
- **Streams are wrapped through the `Stream#iterator` instance field, not `[Symbol.asyncIterator]`.** In openai's `Stream`, both `[Symbol.asyncIterator]()` and `tee()` call `this.iterator()`, so replacing the field covers `for await`, `tee()` (one span, not two) and `toReadableStream()`. The span ends on completion, error, or early `break` (with the partial output). Chat streams fold `ChatCompletionChunk`s (content + indexed `tool_calls` deltas, `usage` from `stream_options.include_usage`).
- **Responses spans are built AFTER the fact** (`responses.ts`): the span is created with the original `startTime` and the caller's captured Laminar context once the response is final. A non-terminal response (`background: true` → `queued` / `in_progress`) is stashed in the module-level `pendingResponses` map by id; a later `retrieve` that sees a terminal status emits ONE span carrying the stashed request data (input, instructions, tools, model). `cancel` of a tracked response emits a failed span ("Response cancelled"); cancelling an untracked one emits nothing. `status: "failed"` and `"cancelled"` (however they arrive: `create`, `retrieve`, or a stream) are marked with `recordException` + ERROR. A `retrieve` (plain or streamed) of a response that already has a span emits nothing: final ids go into the bounded `recordedResponses` set (1000 entries, oldest evicted) so token usage is not double-counted. The check is retrieve-only (`SpanOptions.isRetrieve`); `create` always returns a new id, and the tests reuse ids like `resp_1` across cases. Streams follow the same rules in `finishStream`: the dedup check runs first (keyed by snapshot id, else `params.response_id`, so a streamed retrieve that got no snapshot is covered), and a background stream (or streamed retrieve) that stops on a non-terminal snapshot without an error emits NO span — its merged data is stashed and the later `retrieve` / `cancel` emits the single span with full usage. A stream that errored is spanned immediately and marked recorded. Deliberately stricter than Python, which re-emits on every completed `retrieve` and marks a streamed `cancelled` as OK. Responses stream events: `response.output_text.delta` accumulates text, `output_item.done` records blocks, any event carrying `.response` replaces the snapshot.
- **Chat and responses calls are skipped inside an `@openai/agents` run** (`DISABLE_OPENAI_RESPONSES_INSTRUMENTATION_CONTEXT_KEY`, checked on both `LaminarContextManager.getContext()` and `context.active()`), because the agents processor already emits the LLM span. Completions, embeddings and decisions are still traced. Mirrors Python.
- **openai v3 (`OpenAIApi`, axios-based)** is patched on `OpenAIApi.prototype.createChatCompletion` / `createCompletion`. Results are axios responses, so the body is unwrapped from `.data` and the result returned untouched. v3 streams (`responseType: "stream"`) resolve to a raw Node stream of SSE bytes — only the request attributes are recorded for them. The instrumentation module range is `>=3.1.0`; there is no openai v3 in devDeps, so the test drives a fake `OpenAIApi` class passed as `instrumentModules: { OpenAI: { OpenAIApi } }`.
- **`Decisions` (`POST /decisions`) only exists in openai ≥ 7.40**, so the devDependency was bumped to `^7.40.0` (lockfile resolved with `pnpm install --config.minimumReleaseAge=1440`, see the OpenRouter note). The resolver treats `Decisions` as optional. The attribute mapping matches the Python Decisions wrapper and the AI SDK `experimental_decide` span: string input → user message, `questions` → `gen_ai.request.structured_output_schema`, answers JSON → one assistant message.
- `gen_ai.system` is derived from the client's `baseURL` (`getVendorFromUrl`: OpenRouter, Azure, etc., default `openai`); `gen_ai.request.base_url` is always set. Content attributes (`gen_ai.input.messages`, `gen_ai.output.messages`, `gen_ai.tool.definitions`) sit behind `traceContent`; the structured-output schema does not.
- Tests (`test/openai.test.ts`) keep one nock-cassette case; everything else uses a stub `fetch` + `maxRetries: 0` routed by URL path and method. Chat streams are `data: <json>\n\n` … `data: [DONE]\n\n`; Responses streams are `event: <type>\ndata: <json>\n\n`; both need `content-type: text/event-stream`.
- Not ported yet: the Python rollout/debugger caching wrappers. The user scoped LAM-2409 to the basics.
