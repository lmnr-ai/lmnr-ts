# OpenRouter instrumentation

- `@openrouter/sdk` is Speakeasy-generated and **ESM-only**. `chat`/`responses`/`embeddings` are lazy getters on `OpenRouter.prototype` (cached on the instance), so we patch the getters and wrap the send method on the resource instance they return; `callModel` is a plain prototype method. Patch state lives on the prototype under a symbol so a re-`initialize()` only flips `traceContent` instead of double-wrapping.
- **Each resource has its OWN method name and request-wrapper key — `RESOURCE_METHODS` in `index.ts` is the single source of truth**: `chat.send({ chatRequest })`, `responses.send({ responsesRequest })`, `embeddings.generate({ requestBody })`. A flat `send({ model, ... })` throws `SDKValidationError`, and `embeddings` does NOT follow the `<kind>Request` naming, which is why the key is looked up rather than derived from `kind`. `RESOURCE_KINDS` is `Object.keys(RESOURCE_METHODS)`, so adding a resource means one map entry plus its request/response setters. Return types are unions with `EventStream`, so tests cast (`as AsyncIterable<any>` / `: any`) to reach `.id` or `for await`. Fields are camelCase (`maxTokens`, `promptTokens`, `costDetails.upstreamInferencePromptCost`, ...); real cost is in `usage.cost` / `usage.costDetails`.
- **`embeddings` usage is CHAT-key compatible** (`promptTokens`, `totalTokens`, `cost`, `costDetails.upstreamInferencePromptCost`) so `setResponseAttributes` reuses the chat branch; `completionTokens` is simply absent and `safeSetAttribute` skips `undefined`. Its input is stamped as `gen_ai.input.messages = [{ content }]` (no `role`), and it returns before any output handling — nobody wants raw float vectors in a span. It is never streaming.
- **`embeddings.input` has FIVE shapes** (`InputUnion` in `@openrouter/sdk/esm/models/operations/createembeddings.d.ts`): `string`, `string[]`, **`number[]`**, `number[][]`, `Input[]`. Only the last three-plus-`string[]` are batches — a flat `number[]` is ONE token-id sequence and the API returns a single embedding for it (verified live: `input: [15339, 1917]` → one vector, `prompt_tokens: 2`). So `embeddingsInputMessages` must NOT map over a flat number array, or an N-token request is recorded as N one-token documents. Same trap and same fix in the Python instrumentor (`_embeddings_input_messages`) — keep the two in sync.
- **`gen_ai.tool.definitions` sits BEHIND the `traceContent` gate**, alongside `gen_ai.input.messages` / `gen_ai.output.messages` — tool definitions carry user schemas and descriptions, so they are content, not metadata. This matches the Python instrumentor's `should_send_prompts()` gate; the two were aligned deliberately, do not move it back above the gate.
- **Terminal error marking keys off `response.status`, not the stream event `type`** (`responsesErrorMessage` + `ERROR_RESPONSE_STATUSES = {failed, incomplete}`). `responseFromStreamEvents` returns the terminal event's `.response`, which carries `status`, so ONE helper covers streaming and non-streaming. A failing status sets `error.type = response.status` + `setStatus({ code: ERROR, message: error.message ?? incompleteDetails.reason ?? status })`. `cancelled` is deliberately NOT an error (user-initiated). Mirrors Python `responses_error_message` / `ERROR_RESPONSE_STATUSES`.
- `gen_ai.request.reasoning_effort` comes from `reasoningEffort` on `chat` but `reasoning.effort` on `responses` — read both (`request?.reasoningEffort ?? request?.reasoning?.effort`). Likewise the structured-output schema is `responseFormat.jsonSchema.schema` on `chat` and `text.format.schema` on `responses` (`structuredOutputSchema`). Unlike Python, TS has NO Speakeasy `schema_`/`format_` alias trap — the field names are literal here.
- **`callModel` turns bypass `client.responses.send`**: `ModelResult` calls the internal `responsesSend` function directly from `getInitialResponse` / `makeFollowupRequest`. Those two methods are wrapped per `ModelResult` instance to emit the per-turn `openrouter.responses` LLM spans (request attrs read from `result.resolvedRequest` after the call). Tools are wrapped before being handed to `callModel` (TOOL spans named after the function). The parent `openrouter.call_model` span ends when the memoized `executeToolsIfNeeded()` promise settles — every consumption path (`getText`, `getResponse`, streams with tools) awaits it. Known gap: `getFullResponsesStream()` on a tool-less request never calls it, so that parent span stays open.
- The `Tool` type requires `type: ToolType` (an enum exported from the package root — `type: "function" as const` fails tsc); the `tool()` helper is only on the `@openrouter/sdk/lib/tool.js` subpath.
- Cassette recording: call `nock.recorder.clear()` before `nock.recorder.rec(...)` in each test's setup, or every cassette accumulates the requests of all previous tests in the file. Cassettes are named after the test title, so `setupNock(t.name)` throws for a test that has no recording yet — record with `LMNR_TEST_RECORD_VCR=1` before running it in replay mode. **Run `biome check --write` on every new / re-recorded cassette**: root `pnpm lint` formats JSON too and nock's `JSON.stringify(..., null, 2)` output is not biome-formatted (see the root `AGENTS.md` "Formatting / Lint" section).
- **Always pass `dimensions: 8` when recording an embeddings cassette.** `text-embedding-3-small` returns 1536 floats per input by default, which made a 2-input recording 31 KB of noise; `dimensions: 8` brings it to ~2 KB with identical span attributes.
- **Bumping the `@openrouter/sdk` dev dependency:** OpenRouter publishes several times a day and CI runs pnpm 11, which rejects lockfile entries younger than 24h (`ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION`). Local pnpm 10 does not enforce this. Resolve with `pnpm install --config.minimumReleaseAge=1440` (or pick a version from `npm view @openrouter/sdk time` that is older than a day). Do not add it to `minimumReleaseAgeExclude` — that list is only for our own packages.
